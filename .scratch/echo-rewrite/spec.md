# Echo

Status: ready-for-agent
สร้าง: 2026-09-12

---

## Problem Statement

ผู้เล่นอยากได้เครื่องมือช่วยยิงใน CS2 ที่ให้ความรู้สึกเหมือน **"วันที่มือขึ้น"** ไม่ใช่
**"มือของคนอื่น"** — ช่วยในจุดที่มือคนทำได้แย่ (ติดตามเป้าที่สไตรฟ์ใต้แรงสะท้อน) โดยไม่
แย่งการควบคุมไปจากผู้เล่น

มีโปรดักต์เดิมที่ทำสิ่งนี้ได้ดีอยู่แล้ว แต่**ต่อยอดไม่ได้** — เจ้าของไม่สามารถเข้าใจหรือ
เปลี่ยนมันได้ในความเร็วที่ต้องการอีกต่อไป

**สิ่งที่ต้องการคือโปรดักต์ที่เจ้าของเข้าใจทุกบรรทัด และเติบโตต่อได้**

---

## Solution

**Echo คือโปรดักต์ใหม่ ไม่ใช่การเขียนของเดิมใหม่**

สร้างขึ้นทีละขั้น แต่ละขั้นเล็กพอที่จะเข้าใจได้ทั้งหมด และ**เห็นผลได้ด้วยตา**ก่อนขึ้นขั้นถัดไป

ของเดิมกลายเป็น **คลังความรู้** ที่หยิบมาใช้เมื่อถึงขั้นที่ต้องการ — ไม่ใช่แม่แบบที่ต้อง
ถ่ายทอดให้ครบ

### สิ่งที่ **ไม่ใช่** เป้าหมาย

| ไม่ใช่เป้าหมาย | เหตุผล |
|---|---|
| **พฤติกรรมเหมือนของเดิมทุกอย่าง** | Echo เป็นโปรดักต์ใหม่ ความต่างไม่ใช่ข้อบกพร่อง |
| เทียบตัวเลขวัดผลกับของเดิมได้ | ออกแบบการวัดใหม่ได้อิสระ |
| ยกโค้ดเดิมมา | ยกเฉพาะ**ข้อเท็จจริง** ไม่ยก implementation |
| ทำให้ครบทุกฟีเจอร์เร็วๆ | ขั้นละอย่าง เข้าใจก่อนไปต่อ |

---

## หลักการ

สี่ข้อนี้คุมทุกการตัดสินใจ **การขัดหลักการต้องเป็นการตัดสินใจที่ประกาศชัด ไม่ใช่ผลข้างเคียง**

| | หลักการ | ในทางปฏิบัติ |
|---|---|---|
| **P1** | **มือผู้เล่นชนะเสมอ** | ทุกอย่างที่ระบบทำ ผู้เล่นแย่งคืนได้ทันที ไม่ต้องรอ ไม่ต้องปล่อยปุ่ม |
| **P2** | **สงสัยเมื่อไหร่ ไม่ทำ** | หลักฐานที่เก่า ขาด หรือไม่แน่ใจ = ไม่ทำงาน ห้ามเดา |
| **P3** | **เกมต้องไม่รู้สึกถึงเรา** | ไม่เสีย FPS ไม่กระตุก ไม่กิน CPU ตอนอยู่เฉย |
| **P4** | **เข้าใจทุกบรรทัดที่เขียน** | ถ้าอธิบายไม่ได้ว่าทำไมบรรทัดนี้อยู่ตรงนี้ อย่าเขียน |

**P4 คือข้อที่ทำให้โปรเจกต์นี้ต่างจากของเดิม** และเป็นเหตุผลที่ต้องไปทีละขั้น

## User Stories

### ปลายทาง — สิ่งที่ Echo จะทำได้ในที่สุด

1. ในฐานะผู้เล่น ฉันอยากเห็นศัตรูบนจอ เพื่อที่ฉันจะอ่านสถานการณ์ได้
2. ในฐานะผู้เล่น ฉันอยากได้ตัวช่วยปิดมุมเข้าหาเป้าขณะกดปุ่มค้าง เพื่อที่ฉันจะชนะดวลที่ควรชนะ
3. ในฐานะผู้เล่น ฉันอยากให้ตัวช่วยยอมแพ้ให้มือฉันทันทีที่ฉันฝืน เพื่อที่ฉันจะไม่ต้องสู้กับมัน
4. ในฐานะผู้เล่น ฉันอยากได้ตัวช่วยหักล้างแรงสะท้อน เพื่อที่สเปรย์จะอยู่ในเป้า
5. ในฐานะผู้เล่น ฉันอยากให้ไม่มีอะไรทำงานตอนที่ฉันไม่ได้กดปุ่ม
6. ในฐานะผู้เล่น ฉันอยากให้ไม่มีอะไรทำงานตอนเกมไม่ได้อยู่หน้าสุด หรือฉันอยู่ในเมนู
7. ในฐานะผู้เล่น ฉันอยากปรับความแรงของทุกอย่างได้เอง

### ระหว่างทาง — สิ่งที่เจ้าของต้องได้จากการสร้าง

8. ในฐานะเจ้าของ ฉันอยากเห็นผลของแต่ละขั้นด้วยตา เพื่อที่ฉันจะรู้ว่ามันทำงานจริง
9. ในฐานะเจ้าของ ฉันอยากให้แต่ละขั้นเล็กพอที่ฉันจะเข้าใจได้ทั้งหมด
10. ในฐานะเจ้าของ ฉันอยากให้ขั้นที่ไม่ส่ง output มาก่อน เพื่อที่ความผิดพลาดช่วงแรกจะไม่มีผลอะไร
11. ในฐานะเจ้าของ ฉันอยากหยิบความรู้จากของเดิมมาใช้เมื่อถึงขั้นที่ต้องการ ไม่ใช่ยกมาก่อนทั้งหมด
12. ในฐานะเจ้าของ ฉันอยากให้ตรรกะที่ตัดสินใจอะไรสักอย่าง ทดสอบได้โดยไม่ต้องเปิดเกม

## Implementation Decisions

### บันได

```
 1  ต่อโปรเซส CS2 อ่านค่าได้หนึ่งค่า
 2  หาศัตรูเจอ พิมพ์ตำแหน่งออกมา
 3  วาดอะไรก็ได้ทับจอเกม
 4  วาดกล่องบนศัตรู                    ← ฟีเจอร์แรกที่ใช้งานได้
────────────────────────────────────  ยังไม่แตะเมาส์เลย
 5  อ่านเมาส์จริงของผู้เล่น
 6  ส่งการขยับเมาส์ออกไปได้
 7  ขยับเข้าหาเป้า                      ← ตัวช่วยเล็งตัวแรก แบบดิบ
────────────────────────────────────  จากนี้เติมความปลอดภัยทีละชั้น
 8+ มือชนะ · recoil · การพิสูจน์ · ...
```

**กฎของบันได**

- **ขั้นละอย่าง** ไม่ข้าม ไม่ทำสองขั้นพร้อมกัน
- **ทุกขั้นต้องเห็นผลด้วยตา** ไม่ใช่แค่ผ่าน test
- **ขั้นที่ไม่ส่ง output มาก่อน** (1–4) ทำผิดก็แค่วาดผิด
- **ออกแบบตอนถึงขั้นนั้น** ไม่ออกแบบล่วงหน้า
- **ขึ้นขั้นถัดไปได้เมื่อขั้นปัจจุบันอธิบายได้ทั้งหมด**

### สิ่งที่หยิบจากของเดิม — **ข้อเท็จจริง ไม่ใช่โค้ด**

หยิบเมื่อขั้นนั้นต้องการ ไม่ยกมาก่อน

| ข้อเท็จจริง | ใช้ที่ขั้น | ทำไมไม่เขียนใหม่ |
|---|---|---|
| ตาราง offset ของ CS2 | 1, 2 | เป็นผลของการไล่แกะ ไม่ใช่ตรรกะ — เขียนใหม่ = ไล่หาใหม่หลายสัปดาห์ |
| การแปลงองศา → จำนวนนับเมาส์ | 6, 7 | สอบเทียบกับเมาส์จริงแล้ว |
| เรขาคณิตของ hitbox | 4, 7 | แกะจาก asset ของเกม |
| **บัญชีเงื่อนไขปฏิเสธ 61 ข้อ** | **8+** | บั๊ก 61 ตัวที่เคยเจอในรอบจริง — **นี่คือคลังที่มีค่าที่สุด** |
| บทเรียนจากความล้มเหลว | 7, 8+ | ดูหัวข้อถัดไป |

**ทุกอย่างที่เหลือเขียนใหม่** — ตรรกะ · โครงสร้าง · test · การวาด · การส่ง input

### สิ่งที่ตัดสินตอนถึงขั้นนั้น ไม่ตัดสินตอนนี้

โครงสร้างโมดูล · รูปแบบการจัดการสถานะ · การแบ่ง phase · รูปแบบการปฏิเสธ · การวัดผล

**ตอนนี้ยังไม่มีข้อมูลพอที่จะตัดสินเรื่องพวกนี้ และการตัดสินไปก่อนคือการเดา**

## Testing Decisions

### อะไรคือ test ที่ดี

- **ทดสอบพฤติกรรมภายนอก ไม่ใช่วิธีที่มันทำ**
- **ตรรกะที่ตัดสินใจอะไรสักอย่าง ต้องทดสอบได้โดยไม่เปิดเกม** — ถ้าทดสอบไม่ได้ แปลว่า
  มันพันกับการอ่านเกมมากเกินไป แก้ที่โครงสร้าง ไม่ใช่แก้ที่ test
- **เวลาเป็นค่าที่ส่งเข้าไป ไม่ใช่การรอ** — test ที่ `sleep` คือ test ที่ทดสอบ scheduler
- **test ใหม่ต้องแดงด้วยเหตุผลที่มันอ้าง** — ก่อนรับเข้า ให้ลบเงื่อนไขที่มันอ้างว่าตรึงไว้
  แล้วรันทั้งชุด ต้องแดงเฉพาะตัวนั้น

### ห้ามทำ

- **test ที่อ่านข้อความ source ของไฟล์อื่น** — ของเดิมทำแล้วพัง จนต้องมีกฎห้ามจัดรูปแบบโค้ด
- **test ที่ต้องเปิดเกมถึงจะรันได้**
- **mock ของโปรเซสเกม** — การอ่านเกมพิสูจน์ด้วยการเห็นมันทำงาน ไม่ใช่ด้วย test

### ขั้น 1–4 แทบไม่มี test

มันคือการต่อท่อและการวาด **พิสูจน์ด้วยตา** test เริ่มมีความหมายจริงตอนมีตรรกะที่ตัดสินใจ
— ขั้น 7 เป็นต้นไป

## Out of Scope

- **ทำให้พฤติกรรมเหมือนของเดิม** — ไม่ใช่เป้าหมายอีกต่อไป
- **ยกโค้ดเดิมมา** — ยกเฉพาะข้อเท็จจริง
- **ออกแบบสถาปัตยกรรมล่วงหน้า** — ออกแบบตอนถึงขั้นนั้น
- **ทำหลายขั้นพร้อมกัน**
- **ฟีเจอร์ที่ยังไม่ถึงคิว** — Trigger · Nade · เมนู · การวินิจฉัย ยังไม่อยู่ในบันไดตอนนี้
- **ไล่ประสิทธิภาพก่อนมีอะไรให้วัด**

## Further Notes

### บทเรียนจากของเดิม — หยิบมาใช้ตอนถึงขั้น 7+

ทั้งสามข้อเป็น *อาการ → การวัด → สาเหตุ → การแก้* ที่เกิดขึ้นจริงและแก้ไปแล้ว
**อ่านก่อนถึงขั้นนั้น จะประหยัดเวลาไปมาก**

**K1 — ลำดับการคำนวณ recoil กับการนำเป้า สลับกันไม่ได้**
เคยทำ recoil ทีหลัง ผลคือชดเชยสองเท่า + อาการสั่นเป็นจังหวะตามการยิง → ภาพสั่น
ต้องวางแผน recoil ก่อน แล้วให้ตัวนำเป้ามองทิศ**หลัง**การชดเชย

**K2 — ห้ามตีความการขยับมือ ณ จังหวะที่กดปุ่ม ว่าเป็นการแย่งคืน**
เคยทำ แล้วการกดขณะมือกำลังขยับ — *ซึ่งคือสิ่งที่ผู้เล่นทุกคนทำ* — ทำให้ระบบข้ามการทำงาน
ทั้งรอบ **วัดได้ว่าเกิด 6 ครั้งทุก 30 วินาทีของการเล่น** และคือที่มาของอาการ
*"กดแล้วไม่มีอะไรจับ"*

**K3 — การหมุนตัวเลือกลงเพื่อลดอาการ อาจทำให้อาการแย่ลง**
ถ้าฝั่งสะสมกับฝั่งใช้ถูกคูณด้วยตัวคูณไม่เท่ากัน ที่ค่า 0 จะไม่มีอะไรมาล้างค่าที่สะสมไว้เลย

### บทเรียนที่ Echo เห็นเอง

ต่างจากหัวข้อบน — ไม่ได้รับมรดกมาจากของเดิม แต่เห็นจาก log ของตัวเองระหว่างสร้าง

**E1 — pointer ของ pawn เปลี่ยนทุกครั้งที่เกิดใหม่ ห้าม cache**

log ของขั้น 3 บันทึกวงจร ตาย → ดูคนอื่นเล่น → เกิดใหม่ ไว้ครบ และ address เปลี่ยนสามครั้ง
ในสามสิบวินาที

```
health=100  pawn=A     อยู่ในรอบ
pawn=none              ตาย
health=0    pawn=A     ศพยังถูกอ้างถึงชั่วครู่
health=0    pawn=B     ← address เปลี่ยน
health=100  pawn=C     ← เปลี่ยนอีก เกิดใหม่
```

**ต้องอ่าน pointer ใหม่ทุก tick** ถ้าเก็บไว้ใช้ซ้ำจะได้ข้อมูลจากหน่วยความจำที่เกมปล่อยไปแล้ว
และอาจถูกจองใหม่เป็นอย่างอื่น — **อ่านได้ ไม่ error แต่เป็นขยะ** ซึ่งเป็นความล้มเหลวที่แย่ที่สุด
เพราะมันเงียบ

นี่คือเหตุผลที่ของเดิมมีกลไกเรื่องอัตลักษณ์และรุ่นทั้งชุด — เราเห็นสาเหตุด้วยตาเองแล้ว
ไม่ใช่รับมาเป็นกฎลอยๆ

**ผลต่อขั้นถัดไป:** ขั้น 4 ต้องเดินรายการ entity ซึ่งเต็มไปด้วย pointer แบบเดียวกันนี้
เป็นสิบๆ ตัว ปัญหาเดียวกันจะใหญ่ขึ้นสิบเท่า

**E2 — "ไม่มีอยู่" เป็นสถานะปกติ ไม่ใช่ความล้มเหลว**

pawn เป็น null ตลอดเวลาที่อยู่ในเมนู ระหว่างรอบ และตอนดูคนอื่นเล่น ซึ่งเป็นเวลาส่วนใหญ่
ของการเปิดเกมทิ้งไว้ โค้ดที่ถือว่านั่นคือ error จะส่งเสียงตลอดเวลาโดยไม่มีอะไรผิด

และการอ่านทะลุ pointer อาจล้มเหลวได้เพราะ pawn ถูกปล่อยระหว่างการอ่านสองครั้งในจังหวะเดียว
— **ถือเป็น "ตอนนี้ไม่มีผู้เล่น" แล้วลองใหม่ tick หน้า ไม่ใช่ความผิดพลาด**

### รูปแบบความล้มเหลวที่ต้องระวังตั้งแต่แรก

> **กฎเปลี่ยน → เงื่อนไขกลายเป็นค่าคงที่ → ส่วนที่อยู่ใต้มันตายเงียบ → ไม่มีอะไรแจ้งเตือน**

เกิดกับของเดิม 2 ครั้ง ครั้งหนึ่งไม่มีใครรู้อยู่ 15 เวอร์ชัน

**ราคาถูกที่สุดในการกัน: ทุกเงื่อนไขที่ตัดสินใจมีตัวนับของตัวเอง และตัวนับที่ไม่เคยขยับ
คือการค้นพบ ไม่ใช่ความเงียบ** — เริ่มทำตั้งแต่ขั้นที่มีเงื่อนไขแรก

### สิ่งที่โปรดักต์เดิมทำถูกและควรรักษาไว้

- **ไม่มีเครื่องหมายงานค้างเลยสักตัวทั่วทั้งโปรเจกต์** — ไม่ทิ้งปัญหาที่รู้แล้วไว้โดยไม่บันทึก
- **หลักฐานมาก่อนการแก้** — อย่าแก้บนสมมติฐาน สาเหตุที่อธิบายขนาดของสิ่งที่วัดได้ไม่ได้
